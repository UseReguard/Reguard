# Licensing

This document explains the licensing position of this
repository. It is not a substitute for legal advice.

## What this project is

This project is **source-visible** but **not open source**.

Open-source licenses (MIT, Apache 2.0, BSD, GPL, AGPL, MPL,
BSL, PolyForm, and the like) all grant some form of permission
to use, modify, or redistribute the software without a separate
commercial agreement. We do not want that. We want the source
to be readable and auditable while execution rights remain
commercial.

## What the current LICENSE permits

The `LICENSE` file in the repository root is a copyright
notice. It permits inspection of the source under GitHub's
platform terms and reserves all other rights to the copyright
holder.

It does not grant any of the following, even for non-commercial
or evaluation purposes:

- a license to run the software;
- a license to modify the software;
- a license to redistribute the software;
- a license to host the software as a service;
- a license to use the software in any product or workflow.

## What the hosted service changes

When the planned hosted free manual-check service launches, end
users will be able to run a check on a public repository
through our infrastructure **without** receiving a license to
the software itself. The license to execute remains with us.
The service terms (a separate document, not yet published)
will describe acceptable use of the service.

Treat the hosted free service as access to compute, not as a
software license.

## How commercial execution rights will be granted

Paid customers will receive execution rights through a
separate written commercial agreement tied to their
subscription. The agreement will cover:

- scope of permitted execution;
- conditions for using automated GitHub integration;
- retention and treatment of evidence;
- revocation on non-payment;
- prohibited uses (resale, redistribution, training
  competing products, etc.).

Until the agreement is finalized, no commercial execution
right is implied.

## Contributions

Third-party contributions will require a contributor
license agreement (CLA) before any non-trivial patch is
accepted. The CLA will route sufficient rights to the project
so that we can ship the contribution under our proprietary
model without contaminating the copyright position. The CLA
does not exist yet; do not send substantial patches until it
does.

Until the CLA exists, the safest assumption is:

> The copyright holder accepts no outside copyright
> contributions to this repository.

## What still needs qualified legal review

The current setup is intentionally provisional. Before any
commercial launch the following need a qualified software /
intellectual-property lawyer:

- the final LICENSE text;
- the hosted-service terms of use;
- the paid subscription agreement;
- the contributor license agreement;
- the data-processing addendum for evidence that may contain
  user-submitted repository contents;
- the trademark strategy for the product name.

Until those documents are finalized, treat this repository
and the existing `LICENSE` file as the copyright holder's
current intent, not as a binding legal instrument.
